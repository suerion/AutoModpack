# Server Configuration
------------------------------------

AutoModpack works well with its default configuration, and many servers can be used without changing any settings.

As your setup becomes more advanced, you may want to customize which files are synchronized, how players reach the AutoModpack host, or which client requirements are enforced.

This guide explains the most important configuration areas and uses practical examples based on a real modded server setup.

------------------------------------
## Configuration File
------------------------------------

The server configuration is stored in:

```text
~/.minecraft/automodpack/automodpack-server.json
```

AutoModpack creates this file automatically the first time the server starts with AutoModpack installed.

Always modify the file generated by your installed AutoModpack version instead of replacing it with a configuration copied from another server.

After changing the configuration, reload it using:

```text
/automodpack config reload
```

You can also restart the server.

------------------------------------
## Default Configuration
------------------------------------

For many servers, the default configuration is all you need.

By default, AutoModpack already synchronizes server mods, KubeJS content except `server_scripts`, and emotes. It also allows players to keep common personal settings, excludes recognized server-only and unnecessary files, generates the modpack on startup, requires AutoModpack on clients, and uses the recommended network and security defaults.

Customize the configuration when you need additional synchronized files, manual exclusions, editable client settings, extra client-only content, custom network routing, different client requirements, or advanced hosting and security behavior.

The complete generated default configuration is available here:

[→ Server Configuration Reference](configuration/server-config)

## Practical Configuration Examples
------------------------------------

The following examples are based on a real modded server configuration. They show the most common changes without copying an entire production configuration.

### Synchronizing and Excluding Files

A practical `syncedFiles` setup may look like this:

```json
"syncedFiles": [
  "/mods/*.jar",
  "!/mods/luckperms*.jar",
  "!/mods/ledger*.jar",
  "!/mods/chunky*.jar",

  "/config/**",
  "!/config/luckperms/**",
  "!/config/worldedit/**",

  "/kubejs/**",
  "!/kubejs/server_scripts/**",

  "/resourcepacks/**",
  "/shaderpacks/**",
  "/emotes/*"
]
```

Entries without `!` include matching files or folders.

Entries beginning with `!` exclude matching content.

This approach allows you to include complete folders first and then remove server-only mods, private configuration files, or other content that players do not need.

AutoModpack excludes its own mod file automatically. You do not need to add a separate exclusion for the AutoModpack `.jar`.

Do not copy exclusion rules from another server without checking them. Every modpack uses a different combination of client-required and server-only files.

Learn more:

[→ Synced Files](configuration/synced-files)

## Modpack Generation
------------------------------------

During modpack generation, AutoModpack scans all configured synchronized content and builds the information required by clients.

This includes files synchronized directly from the server and additional client-only content placed inside `host-modpack/main`.

The generated information is stored in:

```text
automodpack_content.json
```

AutoModpack clients use this file to determine:

- Which files belong to the modpack
- Which files have changed
- Which files need to be downloaded or synchronized
- Where files should be downloaded from

With `generateModpackOnStart` enabled, AutoModpack regenerates the modpack information whenever the server starts.

If automatic generation is disabled, regenerate the modpack manually after adding, removing, or changing synchronized content.

------------------------------------
## Synchronizing Server Files
------------------------------------

The `syncedFiles` setting controls which files and folders from the server are included in the generated modpack.

Common synchronized content includes:

- Mods
- Configuration files
- Resource packs
- Shader packs
- KubeJS content
- Emotes
- Other files required by players

Avoid synchronizing server-only mods, administrative files, logs, backups, secrets, private configuration data, or KubeJS server scripts.

Only files configured for synchronization are included in the generated modpack.

------------------------------------
## Additional Client-Only Content
------------------------------------

AutoModpack can distribute files that should be available to players but do not need to exist on the server itself.

Place these files inside:

```text
~/.minecraft/automodpack/host-modpack/main/
```

The directory mirrors the normal `.minecraft` folder structure:

```text
automodpack/
└── host-modpack/
    └── main/
        ├── mods/
        ├── config/
        ├── resourcepacks/
        ├── shaderpacks/
        └── ...
```

For example, place a client-only minimap mod inside:

```text
~/.minecraft/automodpack/host-modpack/main/mods/
```

Files placed in the Main directory extend the content synchronized directly from the server. They do not replace server files and are not loaded by the server itself.

Newer AutoModpack versions may provide additional optional Groups for different client content selections.

## Editable Files
------------------------------------

The `allowEditsInFiles` setting defines synchronized files that players may modify locally.

A practical example is:

```json
"allowEditsInFiles": [
  "/options.txt",
  "/config/iris*",
  "/config/sodium*",
  "/config/voicechat/**"
]
```

These files are downloaded as defaults, but players can keep their own settings afterward.

Typical examples include graphics settings, shader settings, voice chat settings, user interface preferences, and other client-side mod configurations.

Only add files that are safe for players to customize.

Learn more:

[→ Allow Edits in Files](configuration/allow-edits-in-files)

## Force Copy Files
------------------------------------

Most mods are loaded directly from AutoModpack's separate modpack directory.

Some mods or libraries require specific files to exist inside Minecraft's standard folders.

Use `forceCopyFilesToStandardLocation` only for these compatibility cases:

```json
"forceCopyFilesToStandardLocation": []
```

Avoid Force Copy unless it is required, because it reduces the advantages of AutoModpack's separate modpack storage and seamless update process.

Learn more:

[→ Force Copy Files](configuration/force-copy-files)

## Removing Old or Conflicting Files
------------------------------------

Removing a file from the current modpack normally only requires deleting it from the server and regenerating the modpack.

The `nonModpackFilesToDelete` setting is intended for files that are not part of the current modpack but still exist on player installations and cause conflicts.

```json
"nonModpackFilesToDelete": {}
```

For security reasons, remote deletions use exact file hashes.

Use this feature carefully and only for files you can identify precisely.

------------------------------------
## Automatic Exclusions
------------------------------------

`autoExcludeServerSideMods` automatically excludes mods identified as server-side only.

```json
"autoExcludeServerSideMods": true
```

Automatic detection may not recognize every server-only mod. Review the generated modpack and add manual exclusions when necessary.

`autoExcludeUnnecessaryFiles` excludes hidden, temporary, empty, disabled, or backup files.

```json
"autoExcludeUnnecessaryFiles": true
```

For most servers, both settings should remain enabled.

## Client Requirements
------------------------------------

The server controls whether AutoModpack is required and which loaders are accepted.

```json
"requireAutoModpackOnClient": true,
"acceptedLoaders": [
  "fabric"
]
```

When `requireAutoModpackOnClient` is enabled, players without AutoModpack cannot continue normally.

When it is disabled, the server can display a configurable message and download link:

```json
"nagUnModdedClients": true,
"nagMessage": "This server provides dedicated modpack through AutoModpack!",
"nagClickableMessage": "Click here to get the AutoModpack!",
"nagClickableLink": "https://modrinth.com/project/automodpack"
```

The server also provides connection and modpack information that AutoModpack stores automatically in each player's `automodpack-client.json`.

Players normally do not need to edit those stored server entries manually.

Learn more:

[→ Client Configuration](configuration/client-config)

## Network & Hosting
------------------------------------

The network settings control how players connect to the AutoModpack host.

You may need to change them when using:

- Port forwarding
- A reverse proxy
- A custom domain
- A tunnel service such as Playit.gg
- A different public port
- A separately hosted download endpoint

The relevant fields are:

```json
"bindAddress": "",
"bindPort": -1,
"addressToSend": "",
"portToSend": -1,
"requireMagicPackets": false,
"updateIpsOnEveryStart": false,
"bandwidthLimit": 0
```

Incorrect network settings can allow players to join Minecraft while preventing the AutoModpack download from starting.

Learn more:

[→ Network Settings](configuration/network-settings)

## Security
------------------------------------

For most servers, the default security settings should remain unchanged.

```json
"disableInternalTLS": false,
"validateSecrets": true,
"secretLifetime": 336
```

`disableInternalTLS` should only be enabled when a trusted external service terminates TLS before forwarding the connection to AutoModpack.

`validateSecrets` protects hosted downloads using temporary client secrets.

`secretLifetime` defines how long those secrets remain valid. The default value of `336` hours equals 14 days.

Certificate verification is handled separately.

Learn more:

[→ Certificate Verification](technical-details/certificate-system)

## Troubleshooting
------------------------------------

If configuration changes do not take effect:

- Reload the configuration using `/automodpack config reload`
- Restart the server
- Check the server log for configuration errors
- Verify that the JSON syntax is valid
- Confirm that you edited the correct `automodpack-server.json`
- Check whether your installed AutoModpack version uses different field names

If invalid values are restored to defaults, the configuration file may be malformed.

Use an editor with JSON validation to avoid missing commas, brackets, or quotation marks.
